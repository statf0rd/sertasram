# sertasram

Кроссплатформенное десктоп-приложение для голосовых и видео-звонков с
демонстрацией экрана — аналог Discord. До 4 участников в P2P-меше на WebRTC.
Цель — качественная демонстрация экрана с высоким FPS и чистым системным звуком.

Платформы: macOS и Windows (Linux — позже).

Документы: [дизайн](docs/superpowers/specs/2026-06-24-discord-analog-voice-app-design.md),
[план Фазы 0](docs/superpowers/plans/2026-06-24-phase-0-signaling-and-foundations.md),
[деплой сервера](DEPLOY.md).

> Проект переименован из `sertas` в `sertasram`. Внутренние имена намеренно
> оставлены прежними, чтобы не ломать совместимость: Java-пакеты `dev.sertas.*`
> (на них завязаны JNI-символы нативных библиотек), bundle id `dev.sertas.app`,
> системные свойства `-Dsertas.*`, переменные `SERTAS_*`, каталог `~/.sertas/`,
> имена `sertas_*.dll`/`libsertas_audio.dylib` и серверный юнит `sertas-signaling`.

## Стек

JDK 21, JavaFX 21, [webrtc-java](https://github.com/devopvoid/webrtc-java) (нативный
libwebrtc), Javalin (сигналинг-сервер), Gradle (wrapper в комплекте — ставить
Gradle не нужно).

## Модули

| Модуль | Ответственность |
|--------|-----------------|
| `protocol` | Сообщения сигналинга + JSON-кодек |
| `signaling-server` | WebSocket-сервер: комнаты, relay SDP/ICE |
| `signaling-client` | WS-клиент на `java.net.http` |
| `media` | Opus SDP-munger, конвертер аудио Float32 → S16 |
| `media-engine` | webrtc-java: движок, peer-сессии, меш, источники экрана/камеры |
| `app-client` | JavaFX-приложение |

## Установка

Готовые сборки - в [релизах](https://github.com/statf0rd/sertasram/releases), Java
уже внутри.

- **Windows:** `sertasram-windows-x64-setup.exe` ставит приложение для текущего
  пользователя, без прав администратора, в `%LOCALAPPDATA%\Programs\sertasram`,
  с ярлыком в меню «Пуск». Если SmartScreen блокирует запуск: «Подробнее» -
  «Выполнить в любом случае». Лог - `%LOCALAPPDATA%\sertasram\sertasram.log`.
  Без установки - `sertasram-windows-x64.zip` и `Запустить sertasram.bat`.
- **macOS:** `sertasram-macos-arm64.dmg` (Apple Silicon) или
  `sertasram-macos-x64.dmg` (Intel). Перетащить `sertasram` в «Программы» и один
  раз снять карантин: `xattr -cr /Applications/sertasram.app`. Лог -
  `~/Library/Logs/sertasram.log`.

Сборки не подписаны, отсюда предупреждения при первом запуске. Адрес сервера в
них не вшит: адрес с токеном вводится в поле «Сервер» и запоминается.

## Запуск

```bash
./gradlew :signaling-server:run     # локальный сервер (порт 8080)
./gradlew :app-client:run           # приложение (в двух терминалах — два участника)
./gradlew build                     # сборка и все тесты
```

В приложении укажите одинаковый код комнаты и разные имена — клиенты установят
P2P-связь и появятся друг у друга со статусом «на связи».

Две копии на одной машине дадут акустическую обратную связь (общий микрофон и
динамики) — для проверки звука используйте две машины или наушники.

## Адрес сервера

В коде адрес не захардкожен (по умолчанию `ws://localhost:8080/signal`). Свой
адрес задаётся одним из источников (по приоритету):

1. `-Dsertas.server=ws://HOST:8080/signal`
2. переменная окружения `SERTAS_SERVER`
3. файл `~/.sertas/server` (одна строка с URL)

Если сервер защищён токеном, он добавляется в URL: `...signal?token=ТОКЕН`.
Поле «Сервер» в окне входа тоже можно отредактировать вручную.

## Статус

Готово и покрыто тестами:

- Сигналинг: протокол, маршрутизация, сервер, клиент, токен-авторизация.
- Реальное P2P-соединение между двумя пирами (ICE/DTLS/SCTP) и полный меш через
  сервер.
- Аудио- и видео-тракты: реальный offer с Opus и `m=video`, музыкальный профиль
  Opus для звука демонстрации.
- Запускаемое приложение: вход в комнату, голосовой звонок, список участников,
  mute, выход.
- Камера отдельным видеотреком рядом с демонстрацией: своя `m=video`, потолок
  1,5 Мбит/с. В звонке - выбор камеры (переключается на ходу) и зеркальное
  превью у себя.
- Раскладка видео: пока кто-то показывает экран, демонстрация идёт крупно, а
  камеры колонкой справа; без демонстраций камеры раскладываются сеткой.
- Пресеты качества демонстрации (см. ниже); выбор камеры и пресета запоминается.
- Запись статистики WebRTC в CSV (см. ниже) и материалы для сравнительных
  замеров с аналогами - [docs/measurements.md](docs/measurements.md).

В планах:

- Переключатели шумоподавления и эхо.

## Пресеты качества

| Пресет | Захват | Видео экрана до | Звук демонстрации (Opus) |
|---|---|---|---|
| Экономный | 720p, 30 к/с | 1,5 Мбит/с | 96 кбит/с |
| Плавный | 720p, 60 к/с | 4 Мбит/с | 128 кбит/с |
| Сбалансированный (по умолчанию) | 1080p, 30 к/с | 5 Мбит/с | 192 кбит/с |
| Чёткий | 1440p, 15 к/с | 6 Мбит/с | 256 кбит/с |

Пресет выбирается рядом с кнопкой «Демонстрация». Битрейты меняются сразу, без
переговорки; идущий показ перезапускается с новым разрешением и FPS. Значения
стартовые, их уточняют замеры.

## Статистика WebRTC

Для настройки пресетов и сравнительных измерений приложение раз в секунду
снимает `getStats` со всех соединений и пишет CSV:

```bash
./gradlew :app-client:run -Dsertas.stats=on
```

Файл - `~/.sertas/stats/stats-ГГГГММДД-ЧЧММСС.csv`; вместо `on` можно указать
каталог. В бандле включается переменной окружения `SERTAS_STATS=on` (запуск
бинарника из терминала).

Одна строка - один RTP-поток на момент снимка: `connection` (`main` - голос,
экран и камера; `demo-audio-out`/`demo-audio-in` - звук демонстрации), `peer`,
`direction` (`in`/`out`), `kind`, `label` (`mic`, `screen`, `camera`,
`screen-audio`), `fps`, `width`, `height`, `bitrate_kbps` (за интервал),
`packets_lost` (накопительно), `loss_pct` (за интервал), `jitter_ms`, `rtt_ms`,
`concealed_pct` (доля аудиосэмплов, замаскированных декодером). У отдачи потери,
джиттер и RTT - из RTCP-отчёта получателя.

## Выпуск релиза

```bash
./scripts/release.sh build 0.3.0             # сборки в dist/0.3.0
./scripts/release.sh publish 0.3.0 notes.md  # релиз v0.3.0 из этих сборок
```

`build` собирает из закоммиченного кода zip и dmg для macOS (Apple Silicon и
Intel) и zip для Windows в `dist/ВЕРСИЯ`. Между шагами сборки проверяются руками,
`publish` выкладывает ровно их (коммит должен быть запушен) с описанием из
`notes.md`. Установщик Windows после публикации собирает workflow
[windows-installer](.github/workflows/windows-installer.yml) (Inno Setup,
[installer/windows/sertasram.iss](installer/windows/sertasram.iss)): он же ставит
его тихо, запускает приложение, удаляет и прикладывает `setup.exe` к релизу.
Нативные DLL берутся из последнего успешного прогона `windows-capture`; его
артефакты живут 90 дней, после этого прогон нужно повторить
(`gh workflow run windows-capture.yml`).

Список ручных проверок перед релизом - [docs/checklist.md](docs/checklist.md).

## Заметки по реализации

- Нативный артефакт webrtc-java выбирается по платформе сборки
  (`media-engine/build.gradle.kts`).
- Исключение из колбэка WebRTC рушит JVM — все колбэки в `PeerSession`
  обёрнуты и направляют ошибки в `Signals.onError`.
- Нативные объекты освобождаются строго по зависимостям (трек нельзя
  `dispose()`, пока его держит sender).
- В меше offer инициирует пир с меньшим id — обе стороны выбирают одного
  инициатора независимо, без гонки.
- Микрофон идёт через переключаемую обработку (APM); звук демонстрации — отдельным
  треком в обход обработки, стерео Opus.
- Звук демонстрации отдаётся с отдельного движка с ADM `kDummyAudio` (без потока
  захвата): любой ADM с захватом (реальный или headless) кормит все `AudioSendStream`
  фабрики и вместе с `pushAudio` даёт двух производителей — libwebrtc падает на
  `RTC_CHECK_RUNS_SERIALIZED`. Принимается он на главном движке — реальный ADM
  играет его сам (стерео, такт устройства). Push-поток не досылает тишину на
  каждом пустом тике (джиттер захвата → лишние кадры → треск у зрителя), только
  при длительном голоде источника.
- Windows: микрофон и динамики выбираются явно (по id), а не через «устройство
  связи» (роль eCommunications) — иначе Windows приглушает остальные звуки на 80%
  у каждого участника, как только стартует ADM (`-Dsertas.audio.role=comm` — старое
  поведение).
