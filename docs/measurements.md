# Замеры: звук демонстрации и FPS

Как сравнить sertasram с аналогами (Discord, Zoom, Telegram, Google Meet, Jitsi) одинаково для всех.

## Правила

- Одни и те же два компьютера и одна сеть для всех приложений, по 3 прогона на приложение.
- Громкость плеера и системы у отправителя - 100%, посторонние звуки выключены.
- В каждом приложении включить максимальное качество демонстрации и передачу звука, если она есть. В sertasram: «Демонстрация» и «Звук демонстрации», пресет «Сбалансированный» (для замера FPS - «Плавный - 720p60»).
- Если приложение не передаёт системный звук (Meet и Jitsi в браузере на macOS), это тоже результат: записать в таблицу.

## Материалы

```bash
./scripts/measure/make-test-media.sh
```

Файлы появятся в `build/test-media` (в git они не хранятся, их можно раздать как есть):

| Файл | Для чего |
|---|---|
| `sweep-20hz-20khz.wav` | свип 20 Гц - 20 кГц за 20 с: где кончается спектр |
| `lr-check.wav` | 0-2 с тон только слева, 3-5 с только справа, 6-10 с 440 Гц слева и 660 Гц справа: дошло ли стерео |
| `music-stereo.wav` | синтезированная музыка 30 с с широким стерео, для сценария «голос поверх музыки» |
| `video-60fps.mp4` | 1080p 60 к/с, в каждом кадре свой счётчик: сколько кадров дошло |

Нужен ffmpeg (`brew install ffmpeg`, на Windows - сборка с ffmpeg.org). Скрипты разбора - bash: macOS, Linux или Git Bash на Windows.

## Звук

1. **Отправитель:** начать демонстрацию со звуком и проиграть файл в плеере (QuickTime, VLC).
2. **Получатель:** записать системный выход.
   - **macOS:** поставить [BlackHole 2ch](https://existential.audio/blackhole/). В «Настройке Audio-MIDI» создать «Устройство с несколькими выходами» из колонок и BlackHole и выбрать его выходом системы, чтобы и слышать, и писать. Запись:
     ```bash
     ffmpeg -f avfoundation -i ":BlackHole 2ch" -ac 2 -ar 48000 -c:a pcm_s24le rec.wav
     ```
     Список устройств: `ffmpeg -f avfoundation -list_devices true -i ""`.
   - **Windows:** поставить [VB-Cable](https://vb-audio.com/Cable/), выход по умолчанию - «CABLE Input». Чтобы слышать, в свойствах записи «CABLE Output» включить «Прослушивать с данного устройства». Запись:
     ```bash
     ffmpeg -f dshow -i audio="CABLE Output (VB-Audio Virtual Cable)" -ac 2 -ar 48000 rec.wav
     ```
     Список устройств: `ffmpeg -list_devices true -f dshow -i dummy`.
3. **Разбор:** найти начало фрагмента в записи (например, в Audacity) и сравнить с эталоном той же командой:
   ```bash
   ./scripts/measure/audio-report.sh rec.wav НАЧАЛО_С ДЛИТЕЛЬНОСТЬ_С
   ./scripts/measure/audio-report.sh build/test-media/music-stereo.wav
   ```
   - **Полосы.** Уровень сигнала выше 4, 8, 12, 16 и 19 кГц. Где запись на 40+ дБ тише эталона, там спектр срезан: это верхняя граница.
   - **Стерео.** Если «разность L-R» на 30+ дБ тише каналов (или `-inf`), звук пришёл моно.
   - **Спектрограмма.** Рядом с записью сохраняется `rec-spectrum.png`, её удобно вставлять в отчёт.

### Голос поверх музыки

Отправитель играет `music-stereo.wav` и в это время говорит в микрофон 10-15 с. Получатель записывает так же, как выше. На записи и спектрограмме видно, режет ли шумоподавление музыку, пока звучит голос. Этот сценарий проверяет главный тезис проекта: в общем голосовом тракте музыка страдает, в раздельных трактах нет.

## FPS

1. **Отправитель:** открыть `video-60fps.mp4` на весь экран с повтором и демонстрировать этот экран.
2. **Получатель:** развернуть окно приложения и записать экран с частотой 60 к/с секунд 40.
   - **macOS** (номер экрана - из списка устройств):
     ```bash
     ffmpeg -f avfoundation -framerate 60 -capture_cursor 0 -i "1:none" -t 40 -c:v libx264 -preset ultrafast -crf 18 rec.mp4
     ```
   - **Windows:** OBS с 60 к/с или
     ```bash
     ffmpeg -f gdigrab -framerate 60 -i desktop -t 40 -c:v libx264 -preset ultrafast -crf 18 rec.mp4
     ```
3. **Разбор:** посчитать уникальные кадры, отбросив первые секунды:
   ```bash
   ./scripts/measure/count-fps.sh rec.mp4 5 30
   ```
   «Кадров в записи» должно быть около 60 в секунду. Если меньше, не успевает сам рекордер, и результат занижен. «Эффективный FPS» - сколько разных кадров реально дошло.

В sertasram FPS можно сверить со статистикой WebRTC: у получателя строки `in` / `video` / `screen`, столбец `fps`. Статистика включается так:

```bash
SERTAS_STATS=on путь/к/sertasram.app/Contents/MacOS/sertasram
```

На Windows: `set SERTAS_STATS=on`, затем запуск `Запустить sertasram.bat` из того же окна. Файл появится в `~/.sertas/stats/` (на Windows - `%USERPROFILE%\.sertas\stats\`).
